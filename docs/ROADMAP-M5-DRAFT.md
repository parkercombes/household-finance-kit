## Why M5 changes shape

The target user is a Tiller user who is comfortable in a spreadsheet and has never opened a terminal. For that person the current M5 (init skeleton, hook wiring, renderers) still ends at a command line and three YAML files. The reshaped M5 keeps every existing item and adds the pieces that remove YAML, git, and the terminal from the default path:

- Config is derived from the workbook the user already owns; `hfk init` interviews instead of copying a skeleton.
- The plan can live in an `HFK Plan` tab inside the Tiller workbook, read-only, so the editor is the spreadsheet. This replaces the M10 plan editor.
- The private instance is a folder, not a git repo. Git is opt-in for people who customize.
- The local read-only web front door and a double-clickable launcher move from M10 into M5, because M5 already produces HTML.
- AI is an escape hatch, not a requirement. The documented rule: AI may read the config and the code, never the workbook.

Every item below keeps the existing invariants: the Tiller workbook is opened read-only and never saved (ADR-0001), the toolkit never reads its own directory for user data, nothing binds to anything but `127.0.0.1`, and examples use only Alex, Sam, Example Bank, and round numbers.
